# ARC unified assessment framework (skeleton)

This repository provides a lightweight, extensible skeleton for a **unified assessment framework for ARC-style tasks**. It is designed around multiple dimensions beyond pure accuracy:

- **Definition** – learn or synthesize a transformation program from a few input–output examples.
- **Classification** – decide whether a candidate example is generated by the same underlying rule.
- **Constrained generation** – generate new input–output examples that obey the underlying rule.
- **Editing** – repair corrupted outputs (or programs) so they again satisfy the task rule.

The current code focuses on **structure**, not full functionality. Many functions deliberately raise `NotImplementedError` or use dummy metrics; they are meant to be filled in as you develop your experiments.

## Layout

- `arc_framework/`
  - `__init__.py` – exports basic grid helpers.
  - `grids.py` – shared `Grid` and `GridPair` types and utilities.
  - `tasks/`
    - `base.py` – `ArcTask` abstraction and simple metadata types.
    - `arc_dataset.py` – placeholders for loaders over concrete ARC datasets.
    - `registry.py` – registry for named task sets (original ARC, synthetic, re_arc, …).
  - `dimensions/`
    - `base.py` – shared `DimensionConfig`, `DimensionInstance`, `DimensionResult`, `DimensionEvaluator`.
    - `definition.py` – skeleton evaluator for the definition dimension.
    - `classification.py` – skeleton evaluator for classification.
    - `constrained_generation.py` – skeleton evaluator for constrained generation.
    - `editing.py` – skeleton evaluator for editing.
  - `integrations/`
    - `re_arc_adapter.py` – best-effort loader around `external/re_arc` verifiers.
    - `arc_gen_adapter.py` – best-effort loader around `external/ARC-GEN`.
  - `evaluation/`
    - `metrics.py` – simple helpers such as scalar accuracy.
    - `runner.py` – thin orchestration for running dimensions with user-provided prediction functions.
- `external/`
  - `ARC-GEN/` – vendored ARC-GEN repository (used via the adapter).
  - `re_arc/` – vendored re_arc repository (used via the adapter).
- `configs/`
  - `example_definition_eval.yaml` – example configuration for definition experiments.
- `tests/`
  - `test_grids.py` – basic tests for grid helpers.
  - `test_dimensions_sanity.py` – sanity checks for dimension skeletons.
  - `test_integrations_arc_gen.py` – smoke test for the ARC-GEN adapter.

## Quick start

Create and activate a virtual environment, then install development dependencies:

```bash
python -m venv .venv
.venv/Scripts/activate  # on Windows
pip install -r requirements.txt
```

You can then run the tests:

```bash
pytest
```

## Using the skeleton

At a high level, you will:

1. **Load tasks** into `ArcTask` objects (by implementing `arc_framework.tasks.arc_dataset.load_task` / `iter_tasks`).
2. **Construct evaluators** for the dimensions you care about (e.g. `DefinitionEvaluator`, `ClassificationEvaluator`, …).
3. **Provide prediction functions** that map generated instances to model predictions.
4. **Run evaluation** via `arc_framework.evaluation.runner.run_all_dimensions`.

Example (pseudocode):

```python
from arc_framework.dimensions.definition import DefinitionEvaluator
from arc_framework.evaluation.runner import run_all_dimensions
from arc_framework.tasks.arc_dataset import iter_tasks
from arc_framework.tasks.base import DimensionName

tasks = list(iter_tasks(split="train"))
definition_eval = DefinitionEvaluator()

def predict_definition(instances):
    # TODO: call your model here
    return ["# program text here" for _ in instances]

evaluators = {DimensionName.DEFINITION: definition_eval}
predict_fns = {DimensionName.DEFINITION: predict_definition}

summary = run_all_dimensions(evaluators, tasks, predict_fns)
print(summary)
```

This structure should give you a solid base to integrate concrete ARC datasets, models, and richer metrics over time.

## Latest Kimi evaluation commands (OpenRouter `:nitro`)

Requires `OPENROUTER_API_KEY`. `:nitro` shares the same `KimiK25/` output dirs as the base model id, so these resume existing run tags.

**ARC-AGI-1 train (multi-dimension):**

```bash
python scripts/run_all_dimensions_eval.py \
  --model moonshotai/Kimi-K2.5:nitro \
  --provider openrouter \
  --reasoning-effort low \
  --seed 77 \
  --run-tag Evaluation_Run_kimi_timeout420_test \
  --batch-size 100
```

**Test2 / P-ARC (multi-dimension):**

```bash
python scripts/run_all_dimensions_eval.py \
  --task-source test2 \
  --model moonshotai/Kimi-K2.5:nitro \
  --provider openrouter \
  --reasoning-effort low \
  --seed 77 \
  --run-tag Evaluation_Run_kimi_Test2_seed77_low \
  --batch-size 50
```



## ARC-AGI-1 evaluation split — output grids (OpenRouter)

Pure output-grid generation (the "normal ARC setting"): training demonstrations plus one
test input, model returns the output grid. Same prompt and parser as the training-split
runner — only the task source differs.

The 400 evaluation tasks are read from `external/re_arc/arc_original.zip`
(`arc_original/evaluation/`); an extracted `external/arc_original_eval/` directory is used
instead when present. Results are written to
`evaluation/output_grid_eval_results/<ModelAlias>/ARC1Eval/<Run1|Run2>/<run_tag>/`, so they
sit alongside — and never collide with — the training-split runs.

Requires `OPENROUTER_API_KEY`.

**Kimi K2.5:**

```bash
python scripts/run_output_grid_eval_arc1_eval_batch.py \
  --all-eval \
  --model moonshotai/Kimi-K2.5:nitro \
  --provider openrouter \
  --reasoning-effort low \
  --run-tag Evaluation_Run_kimi_arc1_eval_output_grid_run1 \
  --batch-size 50
```

**MiniMax M2.5:**

```bash
python scripts/run_output_grid_eval_arc1_eval_batch.py \
  --all-eval \
  --model minimax/minimax-m2.5:nitro \
  --provider openrouter \
  --reasoning-effort low \
  --run-tag Evaluation_Run_minimax_arc1_eval_output_grid_run1 \
  --batch-size 50
```

Re-run the same command to continue: `--skip-completed` (default) skips tasks that already
have a non-error result under the run tag, so 400 tasks can be walked in `--batch-size`
chunks. Useful extras:

- `--all-test-indices` — evaluate every test example (19 of the 400 eval tasks have 2);
  artifacts for index > 0 are named `<task_id>_test<idx>_output_grid_eval_*.json`.
- `--tasks <id> …` / `--tasks-file <path>` — run a subset instead of `--all-eval`.
- `--retries` / `--retry-backoff-s` / `--no-retry-eval-failures` — transient-error and
  parse-failure retry budget. Failures that exhaust it are logged as
  `<task_id>_output_grid_eval_error_*.json` and are not treated as completed on resume.
